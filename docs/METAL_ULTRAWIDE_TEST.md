# Local native Metal ultrawide test

Base: Wooloomooloo2/bloodborne_mac_port `master` at `030346a09c313572e87f52fdf75f27d2b80257b3` (0.5.3 cleanup). Local branch: `metal-ultrawide-test`; app version: `0.5.3-ultrawide.3`. No upstream merge or public release.

- Keep upstream's native Metal renderer, command recording, shader compiler and memory fixes. Do not transplant the older Vulkan/KosmicKrisp engine or driver.
- Add a launcher Ultrawide toggle and native 32:9 / 21:9 presets. Keep Kyo's camera-aspect, logical UI viewport and screen-coordinate fixes; exclude the guest scene-allocation and heap instructions. Render scene geometry into full selected-size Metal host targets with upscaling off. Test setting: **3840×1080**, 60 FPS cap.
- Keep guest scene allocations at 1920×1080; `ultrawide_res` selects the host scene/output size. `BB_UPSCALER=off` keeps host resizing/composition available without temporal upscaling (the old `none` disabled that machinery). The renderer and FPS badge use the same selected output dimensions. Restart to change the camera aspect; in-game output/upscaler controls remain disabled for this trial. Upstream compute/post-processing paths still use their guest-size surfaces where required; this does not make every pass run at the wider resolution.
- Do not expand guest heaps or apply scene startup-resolution writes. Wide Scaleform/UI coordinates are allowed and mapped 1:1 onto host UI targets; scene/display-copy coordinates still scale from guest size. Keep retail direct memory (5056 MiB; 6 GiB Metal arena). Clear the previous test's automatic 9152 MiB override on restart; preserve explicit developer overrides and unrelated patches. Reject conflicting built-in startup-resolution/heap overrides in wide mode.
- Separate bundle identity, app name, saves, settings and logs: **Bloodborne Metal Ultrawide Test**. The app reads the user's selected game folder; no game assets, UI mod files or saves are included or installed into it. Existing UI mods in that folder are used as-is.
- Retain this port's launcher and controls (`Cmd+,` / L3+R3 for configuration). Our older port's quicksave/quickload and remapping implementation is not transplanted in this first renderer comparison; normal game saving works, and the prior apps/save histories remain available.

Build using `scripts/macos/bootstrap_deps.sh` for x86_64 and arm64, `build_macos.sh`, then `scripts/macos/package_app.sh 0.5.3-ultrawide.3`. This local build uses the macOS 26.5 SDK because the installed linker does not support the default newer SDK. `scripts/macos/build_launcher.sh --test`, Python patch tests, `tests/test_launch_settings.sh`, and `tests/test_settings_keep.cpp` cover persistence, patch sizes and restart/disable behavior. GPU startup, image correctness and FPS must be checked in gameplay; upstream M4 Max measurements are not M2 measurements.

The first trial (`0.5.3-ultrawide.1`) reported ~55 FPS on the M2 Max, but missing legs and stretched triangles while moving. It used the full startup resolution/heap patch, matching upstream's documented above-1080p corruption. Those FPS numbers are not a correct-image benchmark. `.2` removed that path: the user reported no artifacts (~36 FPS in the supplied scene), but gameplay was squeezed/pillarboxed without menus, and menu text stretched. `.3` restores the UI-only coordinates and composes frames even with no movie/HUD draws. Gameplay verification of `.3` remains pending. No shader precision, draw-skipping or model-detail changes are part of this correction.

Validation: patch tests assert guest scene/heap writes are absent and camera/UI dimensions match every preset; settings and launcher tests cover native rendering and disable/restart behavior; UI math tests distinguish wide movie coordinates from guest-size display copies. The Metal scene-resolution test exercises color/depth/stencil roundtrips at native 3840×1080 and 5120×1440.
